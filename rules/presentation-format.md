# HTML Presentation Format (MANDATORY)

All HTML presentations MUST be generated by `agent-output-handler.py`. Do NOT manually build presentation HTML.

**Full technical spec:** `Product Org OS/product-org-plugin/templates/presentations/TEMPLATE-REFERENCE.md`

---

## The Rule

```bash
python "agent-output-handler.py" "<path-to-md-file>" --no-telegram
```

The handler is the single source of truth. It handles brand detection, slide splitting, nav bar, commenting, and browser auto-open. Output goes to `presentations\`.

> **Brand-per-project + commentable (spawn-protocol §2.7).** Presentations MUST use the **commentable template** and the brand **auto-selected by the project being worked on**. Brand auto-detection keys on the project path first, then the title, with `--brand <project-brand>` as an explicit override the orchestrator passes. A markdown `---` on its own line is a **hard slide-break** (used for one-slide-per-agent multi-agent decks); it no longer renders as an in-slide `<hr>`.

## Non-Negotiable Requirements

If you ever need to generate presentation HTML directly (edge cases only), these are mandatory:

### Scrollable Slides (CRITICAL)
```css
/* CORRECT */
.slide { min-height: 100vh; overflow-y: auto; }

/* WRONG — clips content */
.slide { height: 100vh; overflow: hidden; }
```

### Brand-Specific Favicon
Use actual brand icons from `brand-assets/` folder -- embed as base64 PNG inside SVG `<image>` wrappers. **Never hand-draw logos.**

| Brand | Icon Source |
|-------|-------------|
| **«Security Vendor»** | `brand-assets/«security-vendor»-icon.png` |
| **«AI Platform»** | `brand-assets/«ai-platform»-icon.png` |
| **«DTC Brand»** | `brand-assets/«dtc-brand»-icon.png` |
| **«Design Agency»** | `brand-assets/«design-agency»-icon.png` |
| **«Holding Co»** | (TBD) |
| **Product Org OS** | `brand-assets/product-org-os-icon.png` |
| **ProductBeacon** | `brand-assets/productbeacon-icon.png` |
| **Generic** | letter SVG |

Per-brand `--primary` and `--accent` values live in the handler's brand table
and are resolved at render time. They are deliberately not listed here: a
placeholder brand name printed beside its real published colour resolves the
placeholder, which is the residue class this package is scrubbed against.

All logos are embedded as base64 in `agent-output-handler.py`. When adding a new brand: save icon to `brand-assets/`, generate base64, wrap in `<svg><image>` element.

Logos are embedded as inline SVGs (no external dependencies).

### Nav Bar
Fixed bottom, CSS Grid `1fr auto 1fr`, `backdrop-filter: blur(12px)`, `z-index: 100`.

### IIFE Scope
All onclick-bound functions exposed via `window.` (showSlide, promptSlide, closeJump, etc.).

### Hidden Scrollbar
```css
html { scrollbar-width: none; }
html::-webkit-scrollbar { display: none; }
```

### Inline Commenting (Always-On)
`.commentable` divs on every content block. Review slide always last. localStorage persistence.

### No External Dependencies
No reveal.js, no CDN JS/CSS. Only Google Fonts link (Manrope + JetBrains Mono).

## Presentation Content Guidelines — **EVERY presentation, no exceptions** (MANDATORY)

> ⛔ **SCOPE, restated 2026-08-18 because the earlier wording was read too narrowly.**
> These guidelines govern **every presentation rendered for the owner** — not "synthesis decks".
> **Synthesis, options, plans, reviews, status, research, briefs, proposals, reports, one-slide
> answers, decks for third parties that he will present** — all of it. If it goes through
> `agent-output-handler.py`, these apply.
>
> **There is no deck type that is exempt.** Do not scope a future revision of this section back
> to a genre; the original wording said "synthesis slides" because that was the deck in front of
> him at the time, and it was then wrongly read as a limit.

Origin, confirmed 2026-08-16: *"This is exactly how I like my synthesis slides. Can we make it so future ones use the same guidelines used here: bullet points and tables where possible, larger font, clear/simple language, storytelling narrative where it makes sense."*
Scope generalised 2026-08-18 on his instruction: *"make sure these are for all my presentations, not just 'synthesis' presentations."*

Full background + exemplars: memory `feedback_decks_storytelling_no_lingo_rebuild_not_patch`.

| Guideline | What it means in practice |
|---|---|
| **Bullets and tables by default** | Prose paragraphs only where a bullet genuinely cannot carry the idea. Tables: plain-word headers, ≤4 columns, ✅/❌ for verdict columns. |
| **Larger font** | Pass `--font-scale 1.3` to `agent-output-handler.py`. Verified legible at 1280×900. Not optional. |
| **Clear, simple language** | No internal lingo, no unexplained acronyms, short sentences, one idea per slide. Explain the mechanism in everyday words before naming it. |
| **Storytelling where it makes sense** | Narrative spine for engagements and plans. For a situation/options deck, the proven shape is: name the reader's confusion first → one slide per problem → options table with a recommendation → the decisions only he can make. |
| **Decision slides are commentable asks** | He answers via inline deck comments ("Slide 11: Agree"). Every decision gets its own block and an explicit ask. **A numbered decision presented with no recommendation is not settled by a blanket "agree" — re-ask it.** |
| **Every decision carries a recommendation** | Never present a fork and leave it open. State which option you'd take and why, in one line, so "agree" is a complete answer. Options with no recommendation cost him a round-trip. |
| **Lead with the bottom line** | Slide 1 answers the question the deck exists to answer. Never build to a reveal — he may read three slides and stop. |
| **Say what is NOT in doubt** | Every deck that reports problems also states plainly what is working and settled. A deck of only findings reads as a crisis whether or not there is one. |
| **Revisions are reweaves, never patches** | Fold accepted rulings into the spine so the deck reads as if written that way from the start. |

**Verify before he sees it**: headless screenshot QA per memory `reference_html_deck_visual_qa_headless`. **Open it** per memory `reference_open_local_files_in_chrome_via_localhost` — verify by tab title, never by exit code.
